خادم WireGuard على خادمك، بأمر واحد

ByteGuard ينصّب خادم WireGuard بأمر واحد، ويُدير أجهزتك من صفحة ويب، ويستعيد إعداداتك كاملة من ملف نسخة احتياطية واحد بعد إعادة تثبيت الخادم.

curl -fsSL https://bytebalancetech.com/byteguard.sh -o byteguard.sh
sudo bash byteguard.sh
آخر إصدار التوثيق سجل التغييرات

ما يقدّمه

  • ملف تنصيب واحدلنظام Ubuntu 22.04 أو أحدث، أو Debian 12 أو أحدث. البرنامج مضمّن فيه نصاً مقروءاً، فتستطيع قراءة كل ما ينصّبه.
  • إعداد موجّهيكتشف بطاقة الشبكة المتصلة بالإنترنت وعنوان الخادم العام، ويطلب تأكيدهما، ثم يسأل عن المنفذ (الافتراضي 51820).
  • كل حركة بيانات الأجهزة عبر الخادممع PersistentKeepalive = 25 وMTU = 1420.
  • إدارة الأجهزةأضف الأجهزة واحذفها واعرض قائمتها، واعرض الرمز الضوئي (QR) لأي جهاز في أي وقت، وعطّل جهازاً دون حذفه.
  • نسخة احتياطية بعد كل تعديلملف واحد قابل للتشغيل: شغّله على خادم جديد فتعود الشبكة بالمفاتيح نفسها. ويمكن إرساله إلى Telegram ورفعه إلى تخزين متوافق مع S3 مثل Cloudflare R2.
  • واجهة ويب بالعربية والإنجليزيةالأجهزة ورموزها والمتصلون منها والنسخ الاحتياطية وTelegram. تعمل على عنوان الخادم داخل الشبكة الافتراضية فقط.
  • نطاقك الخاص، اختيارياًالواجهة عبر Cloudflare Tunnel دون فتح أي منفذ. يُنشئ البرنامج نفقاً خاصاً به ولا يمسّ أي cloudflared موجود.
  • احترام الجدار الناريقواعد ufw إن كان مفعّلاً، وقواعد iptables في غير ذلك. لا يمسح أي سلسلة قواعد، وعند الإزالة يحذف ما أضافه فقط.

كل شيء يعمل على خادمك وحساباتك. البرنامج لا يجمع أي بيانات، والمفاتيح والأجهزة لا تغادر الخادم إلا إلى وجهات النسخ الاحتياطي التي تختارها.

التنصيب

على خادم جديد يعمل بنظام Ubuntu 22.04 أو أحدث، أو Debian 12 أو أحدث:

curl -fsSL https://bytebalancetech.com/byteguard.sh -o byteguard.sh
sudo bash byteguard.sh

يحوّل هذا العنوان إلى آخر إصدار على GitHub. لتحميل الملف مباشرة من GitHub:

curl -fsSL https://github.com/kenanwahbeh/ByteGuard/releases/latest/download/byteguard.sh -o byteguard.sh

للتحقق من الملف قبل تشغيله قارنه ببصمة SHA-256 المنشورة مع الإصدار:

curl -fsSLO https://github.com/kenanwahbeh/ByteGuard/releases/latest/download/byteguard.sh.sha256
sha256sum -c byteguard.sh.sha256

الإصدار الأول، أي السكربت القديم ذو الملف الواحد، متاح في الإصدار v1.0.0، والإصدار الثاني لا يستورد بياناته.

التحديث

نزّل ملف التنصيب الجديد وشغّله على الخادم بالأمرين نفسيهما المستخدمين في التنصيب. على خادم منصّب مسبقاً يُستبدل البرنامج فقط، وتبقى المفاتيح والأجهزة والإعدادات كما هي، وتبقى الأجهزة متصلة. إذا كانت الواجهة تعمل يُعاد تشغيلها لتعمل بالإصدار الجديد، فتُغلق كل جلساتها ويلزم تسجيل الدخول من جديد.

البدء السريع

يطرح ملف التنصيب أسئلته، ثم يشغّل الشبكة ويعرض إعدادات الجهاز الأول ورمزه الضوئي. لتخطي الأسئلة مرّر --non-interactive مع ما تريد من --iface و--endpoint و--port و--first-device، ويكتشف البرنامج ما لم تحدّده.

تستخدم الشبكة النطاق الخاص 10.66.66.0/24 ما لم تمرّر غيره، مثل --subnet 10.11.12.0/24. يأخذ الخادم أول عنوان فيه، وتأخذ الأجهزة العناوين التالية.

الأوامر

بعد التنصيب يفتح الأمر sudo byteguard قائمةً، والإجراءات نفسها متاحة أوامرَ مستقلة:

الأمرالوظيفة
sudo byteguard add NAMEإضافة جهاز وعرض إعداداته ورمزه الضوئي
sudo byteguard show NAMEعرض إعدادات جهاز ورمزه الضوئي مرة أخرى
sudo byteguard listعرض قائمة الأجهزة
sudo byteguard statusالأجهزة المتصلة واستهلاك كل جهاز
sudo byteguard disable NAMEمنع جهاز من الاتصال دون حذفه
sudo byteguard enable NAMEالسماح لجهاز معطّل بالاتصال من جديد
sudo byteguard remove NAMEحذف جهاز
sudo byteguard port NUMBERنقل الشبكة إلى منفذ UDP آخر، ويحتاج كل جهاز بعدها إلى إعداداته من جديد
sudo byteguard ui setupتشغيل الواجهة وتعيين كلمة مرورها (ui off يوقفها)
sudo byteguard ui tunnelنشر الواجهة على نطاقك عبر Cloudflare (--off يوقفها)
sudo byteguard backupنسخة احتياطية فورية
sudo byteguard backup telegramإرسال كل نسخة إلى محادثة Telegram عبر بوت خاص بك (--off يوقفه)
sudo byteguard backup s3رفع كل نسخة إلى تخزين متوافق مع S3 مثل Cloudflare R2 (--off يوقفه)
sudo byteguard uninstallإزالة الشبكة ومفاتيحها وByteGuard

تُحفظ مفاتيح الخادم والأجهزة في /etc/byteguard/state.json، ولا يقرؤه إلا root. يُولَّد الملف /etc/wireguard/wg0.conf منه، فلا تعدّله يدوياً.

واجهة الويب

شغّل sudo byteguard ui setup لتعيين كلمة مرور وتشغيل الواجهة على عنوان الخادم داخل الشبكة والمنفذ 51821، مثل http://10.66.66.1:51821. افتحها من جهاز متصل بالشبكة، فالعنوان لا يستجيب من أي مكان آخر. الصفحة بالعربية أو الإنجليزية، ويبدّل الزر في الزاوية العلوية بينهما.

إذا أُدخلت ثماني كلمات مرور خاطئة من عنوان واحد يُقفل الدخول منه خمس دقائق، دون أن تتأثر العناوين الأخرى، ومنها عنوانك. لتغيير كلمة المرور استخدم «تغيير كلمة المرور» أسفل الصفحة، وتُغلق بعدها كل الجلسات المفتوحة على الأجهزة الأخرى. إذا نسيت كلمة المرور شغّل sudo byteguard ui setup على الخادم لتعيين كلمة جديدة.

على نطاقك الخاص

شغّل sudo byteguard ui tunnel لنشر الصفحة نفسها على عنوان مثل https://vpn.example.com عبر Cloudflare Tunnel، فتفتحها دون الاتصال بالشبكة ودون فتح أي منفذ. يتطلب ذلك نطاقاً في حسابك على Cloudflare، والخطة المجانية تكفي.

ينصّب البرنامج cloudflared من مستودع حزم Cloudflare الموقّع إن لم يكن موجوداً، ويعرض رابطاً تسجّل منه الدخول إلى Cloudflare وتختار النطاق، ثم يُنشئ نفقاً ويشغّله خدمةً باسم byteguard-tunnel.service. تُحذف شهادة الدخول فوراً لأنها تستطيع إدارة النطاق كله، ولا يبقى على الخادم إلا بيانات اعتماد هذا النفق وحده.

بعد نشر الواجهة على عنوان عام يستطيع كل من يعرف العنوان الوصول إلى صفحة الدخول. استخدم كلمة مرور قوية، وفكّر في وضع Cloudflare Access أمامها.

النسخ الاحتياطي والاستعادة

كل تعديل (إضافة جهاز أو حذفه أو تفعيله أو تعطيله، أو نقل المنفذ) يعيد كتابة ملف النسخة في /var/backups/byteguard/ فوراً. الملف الموجود على الخادم يضيع إذا مُسح الخادم، فأرسله إلى مكان آخر أيضاً:

  • sudo byteguard backup telegram يطلب رمز بوت تُنشئه عبر ‎@BotFather، ثم يرسل كل نسخة جديدة إلى محادثتك.
  • sudo byteguard backup s3 يرفع كل نسخة إلى تخزين متوافق مع S3 (Cloudflare R2 وAWS S3 وBackblaze B2 وغيرها). يجري البرنامج رفعاً تجريبياً قبل حفظ الإعدادات، ويحتفظ بأحدث 10 نسخ.

للاستعادة انسخ ملف النسخة الاحتياطية إلى خادم جديد وشغّله:

sudo bash byteguard-backup-NAME.sh

تتصل الأجهزة تلقائياً إذا احتفظ الخادم الجديد بالعنوان العام نفسه، أو إذا أُعدّت باسم نطاق ووُجّه هذا الاسم إلى الخادم الجديد. إذا تغيّر العنوان أضف --endpoint NEW_ADDRESS، وعندها يحتاج كل جهاز إلى إعداداته من جديد.

النسخة الاحتياطية غير مشفّرة. تحتوي مفتاح الخادم ومفاتيح كل الأجهزة ورمز بوت Telegram ومفاتيح التخزين. من يحصل عليها يستطيع الاتصال بشبكتك، فاحفظها هي والمحادثة التي تُرسل إليها في مكان خاص.

نموذج الأمان

  • ما يُخزَّن: كل شيء على خادمك. يحوي /etc/byteguard/state.json، الذي لا يقرؤه إلا root، مفاتيح WireGuard وبصمة كلمة مرور الواجهة (scrypt) وبيانات اعتماد وجهات النسخ الاحتياطي والنفق.
  • ما يُكشف: WireGuard على منفذ UDP الذي اخترته. تستمع الواجهة على عنوان الخادم داخل الشبكة فقط، وقاعدة الجدار الناري التي تسمح بها مقيّدة بواجهة الشبكة الافتراضية.
  • الحماية من DNS rebinding: لا تجيب الواجهة إلا الطلبات الموجّهة إلى عنوان الشبكة الافتراضية، أو الواردة عبر النفق على الخادم نفسه. حجم الطلبات محدود، ويُقطع الطلب بعد 30 ثانية دون تقدّم.
  • أقل الصلاحيات: تحتفظ خدمة الواجهة بصلاحية واحدة فقط (إدارة واجهات الشبكة)، وترى النظام للقراءة فقط باستثناء مجلدات ByteGuard.
  • ما يغيّره على الخادم: يضيف قواعد الجدار الناري بجانب القواعد الموجودة ويحذفها هي فقط عند الإزالة. لا يوقف IP forwarding أبداً، ولا يمسّ إعداد WireGuard أو نفق Cloudflare لم يُنشئه.
  • الاتصالات الخارجية: لا جمع للبيانات. أثناء الإعداد يسأل api.ipify.org (أو icanhazip.com) لاقتراح العنوان العام، وتتصل ميزة النفق بـ Cloudflare، ولا يحمل أي من هذه الطلبات بياناتك.

التفاصيل في SECURITY.md. للإبلاغ عن ثغرة استخدم Report a vulnerability في تبويب Security في المستودع، لا بلاغاً عاماً.

التطوير

البرنامج مكتوب بلغة Python 3.10 أو أحدث، ويعتمد على المكتبة القياسية وحدها. لبناء ملف التنصيب من المصدر:

git clone https://github.com/kenanwahbeh/ByteGuard.git
cd ByteGuard
python3 tools/build.py                  # writes dist/byteguard.sh
sudo bash dist/byteguard.sh
python3 -m unittest discover -s tests   # unit tests, safe to run anywhere
